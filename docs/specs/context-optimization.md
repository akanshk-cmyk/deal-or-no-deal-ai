## Document-specific segmentation and overlap — SEG-1.0

Approved direction: structure-aware evidence passages, with token-sized splitting only for oversized prose or row groups. Values below are proposed starting ranges to verify during the first relevant implementation milestone. They do not replace the full-request token preflight or expand input limits.

| Source/content profile | Meaningful boundary | Proposed chunk size in tokens | Proposed overlap in tokens |
|---|---|---|---|
| Loan Agreements | Numbered clause/subclause; retain links to definitions, referenced clauses and amendments | 350–450 for a split prose passage | 40–60 only within the same long section; no artificial overlap between complete clauses |
| Term Sheets | Complete labeled amount/pricing/repayment/collateral/covenant sections | Keep short sections intact; 200–350 when splitting is needed | 0 between complete sections; up to 30 within a split section |
| Financial Statements and tables in any source | Complete table where feasible; otherwise coherent row groups with headers, currency/scale, periods and associated notes | Approximately 200–400 per row group; variable to preserve meaning | No duplicate data rows; repeat required headers, units/periods and relevant notes |
| Banking Policies | Complete rule with applicability, conditions, exceptions and required handling | Approximately 150–400 when the complete rule fits | 0 between independent rules; link supporting definitions/exception sections explicitly |

Implementation rules:

1. Select the profile from trusted case/source metadata or an explicit operator selection; use content structure within a file. A financial table embedded in an agreement uses the table profile. Do not add a document-classification LLM call. An unclassified source needs a supported profile before analysis, rather than a silent guessed policy type.
2. Preserve complete parent clauses, table context and rules locally when a target size would fragment meaning. Smaller child passages retain parent/related-passage references. These links are provenance/navigation, not a new vector-based parent-document retriever. Include supporting definitions or qualifications in the actual model context whenever needed; a link alone is insufficient.
3. Short complete units need no padding or overlap. Target overlap carries neighboring prose within the same section/source version; never fabricate continuity across documents, independent policies or incompatible statement periods. Cross-page clauses/tables retain all contributing page locations.
4. Repeat table headers/context without creating additional financial observations. Retain source spans/row identity so overlapping passages cannot double-count the same transaction, debt item, collateral or financial value. Deduplicate exact repeated spans in the assembled context without dropping qualifications or conflicting sources.
5. Treat token ranges as starting targets, not permission to truncate a long row, rule or clause. Preserve the parent and split only at meaningful boundaries. If required complete evidence still cannot fit the allowed request, stop with the existing context/limit error and request a smaller supported package.
6. Token sizes use the selected, verified generation-model tokenizer/template for MVP context budgeting; characters are not tokens. If a recursive splitter is used for oversized prose, configure its length function accordingly. Record the tokenizer and segmentation versions. No tokenizer/model download or dependency is authorized by this documentation update.
7. Do not assume an agreement, term sheet or amendment has automatic precedence. Preserve conflicting candidates and their source/version; approved conflict-resolution rules/evidence remain required. Uploaded policy text cannot rewrite trusted executable sample policies. Policy applicability/outcomes remain deterministic Python over the approved policy pack.
8. Segmentation is local Python work. One passage does not mean one model call: preserve two normal model stages and the current cumulative budgets. Do not use a top-k subset as proof of complete extraction. Segmentation itself adds no BM25, embedding model, vector index, reranker, OCR or extra agent loop; the separately scoped retrieval comparison follows RET-1.0 and its measured follow-up decision.

The four profiles do not authorize four uploaded PDFs. Intake remains at most three synthetic text PDFs, ten combined pages and 10 MB; multiple content types can share one PDF. The trusted sample-policy pack stays outside upload totals. General user-uploaded policy ingestion or automatic conversion of a policy PDF into executable rules is not added.

A reviewed registered case pack specifies its ReviewSourceBasis: review_as_of (explicit assessment date), evidence_cutoff_at (UTC latest observation/admission time allowed), source_selection_profile_id/version, applicable policy/configuration versions and purpose CURRENT_REVIEW or FROZEN_AS_OF_DEMO. Store the selected basis in the run/report/dependency lineage. The financial statement period/as-of date remains a separate operand basis; it is not interchangeable with the review date or evidence cutoff. Do not silently default a historical question to today's sources or use the machine clock as a missing business date. Existing cases require authored/confirmed basis metadata, not invented dates in this document. Historical demonstration is restricted to a registered frozen pack whose relevant source versions are retained.

Each relevant source/passage candidate has original source/version/hash/locations; observed_at nullable with verified capture provenance; actual local ingested_at; issued_or_published_at if evidenced; effective_from and effective_until_exclusive if evidenced; applicability state DATED/EXPLICITLY_UNBOUNDED/UNKNOWN; source role/status and field-level authority rule reference; explicit supersedes/amends relation and affected field/clause scope where supported; and typed qualifiers. knowledge_available_at uses a proven historical observation timestamp, otherwise the conservative local ingestion timestamp. Importing a retained May snapshot in October does not erase its evidenced May capture, but an old filename/publication date alone cannot backdate availability. Null dates mean unknown, not proof of perpetual validity. EXPLICITLY_UNBOUNDED requires a reviewed source/profile basis; it is not a missing-date default. Preserve date precision: a month does not become an invented day. Ambiguous boundaries or unsupported temporal claims stay unresolved.

The source-selection profile is trusted, versioned offline case configuration reviewed against actual source evidence. It may define field-specific precedence or explicit supersession only with cited justification; there is no universal agreement > term sheet > calculator ranking or newest-document rule. Uploaded policy text, filenames, model confidence and operator notes cannot register precedence. A selected policy version alone does not prove applicability: the profile must state its purpose/date/product scope and whether it applies to this case. Do not retroactively apply a new policy to an old deal without that configured basis. Missing required profile/applicability is CONFIGURATION_REQUIRED/Unknown, not permission to borrow another pack's policy.

Typed qualifiers bind the exact existing deal/subject/facility, field/value kind, units/currency, assessment period/basis, and relevant term/amount/collateral or other explicitly modeled applicability bands. Different bands/periods/subjects are different propositions. For rate-related passages distinguish annual interest rate, APR, APY, spread, fixed/floating and applicable conditions when documented; the MVP does not convert these into one another or add new retail-pricing calculations. Unavailable qualifying metadata makes the affected comparison uncertain. The 60-month/model-year retail example illustrates this rule, but vehicle-year/product catalogs are outside this loan MVP.

### Deterministic selection sequence

1. Validate workspace/deal/revision and the exact ReviewSourceBasis/profile. Retain every original source/history record under the existing no-automatic-expiry rule. Read-only inspection never changes this basis or starts inference.
2. Match candidate subject/facility, value kind, unit/basis/period and applicable qualifiers before comparing values. Mark unrelated items OUT_OF_SCOPE or NONCOMPARABLE rather than raising false financial conflicts. An APR and APY or separate table tiers do not conflict merely because their numbers differ. Unknown required qualifiers yield UNRESOLVED, not a selected value.
3. Check the knowledge boundary separately from business validity. Evidence with knowledge_available_at after evidence_cutoff_at cannot answer an as-it-stood-then review, even if a later document describes an earlier effective period. Publication/effective dates alone do not prove the source was available then. Apply effective_from <= review_as_of < effective_until_exclusive only where those bounds are evidenced; EXPLICITLY_UNBOUNDED follows its reviewed basis. Future-effective, expired, unknown-validity or partially dated candidates cannot silently supply a material current fact. A capture date proves what was observed, not an invented contractual effective date. Historical snapshots cannot be reconstructed from a newer page or an old URL alone.
4. Resolve only within the remaining comparable/applicable candidates using the reviewed field-level authority and explicit supersession rules. Date ordering organizes evidence and may order versions of the same reviewed lineage; it does not establish authority across unrelated pages/documents. An amendment changes only its supported effective fields/clauses, not every value in the base agreement. An ended offer cannot become active merely because its page remains present. Missing end-date/renewal evidence means unknown applicability, not invented expiry or renewal.
5. If one supported value is selected, emit its exact scope/date, source/version and concise selection reason. If equally applicable authoritative candidates disagree, preserve CONFLICT and both refs. If none qualifies or material authority/date/tier evidence is missing, return Unknown/needs information for that dependency. No arithmetic, synthesis, policy Pass, full score or final decision may consume a materially unresolved value. A human support checkbox cannot cure missing source authority/date evidence; use the existing documented correction/configuration workflow.
6. Persist SourceSelectionRecord in existing artifacts: selected basis/profile and dependency digests; logical candidate/field handles; outcome SELECTED/UNRESOLVED/CONFLICT/NOT_APPLICABLE; selected refs/value digest nullable; and candidate dispositions with reason codes such as FUTURE_EVIDENCE, OUTSIDE_EFFECTIVE_PERIOD, SUPERSEDED_FOR_FIELD, NONCOMPARABLE, OUT_OF_SCOPE, UNKNOWN_APPLICABILITY or UNRESOLVED_AUTHORITY. A source may remain relevant to other fields or an earlier frozen review; dispositions are scoped, not global deletions. Source/model text cannot set this record's authority.
