## Purpose and authorization

The user requested RAGAS evaluation and five 1–5 scores with specific examples and explanations. This authorizes adding this offline evaluation capability to the specifications. It supersedes the blanket prohibition on automated judging ONLY for this explicitly invoked offline extension. The deal graph, Evidence node, Fixture runs, ordinary application tests, UI navigation, report generation and graph-only notebook still perform no judge inference. Two normal application calls and all per-review limits remain unchanged.

Evaluation design is authorized; package installation, application scaffolding, credentials, model selection, paid evaluator requests and execution allowances remain separate prerequisites. Default ragas_enabled=false; evaluator mode DISABLED until the approved evaluation milestone configures it. No provider/model download or hosted trace is triggered by import, app startup, a saved report or opening evaluation results. Do not select OpenAI or infer spending permission from a Nebius key.

This protocol evaluates saved synthetic artifacts; it never runs the lending graph to obtain an answer, edits a score/source/claim, grants HUMAN_SUPPORTED, resolves an issue, resumes a review or changes PanelDecision. Reviewer judgment and existing critical release gates remain authoritative. HHH alignment is broader than a RAGAS score: arithmetic, source authority/currentness, permissions, privacy, safe abstention and external-action boundaries require their existing checks.

## Two distinct score families

| Family | Definition / scale | Implementation direction |
|---|---|---|
| USER-RUBRIC-1.0, RAG-R01–05 | The user's five dimensions, strict integer1–5, each with explanation and traceable examples | Five custom RAGAS metric projections backed by ONE shared structured evaluator bundle for each frozen sample/configuration. All five projections read the same validated bundle; do not call the model five times to read five fields |
| Native RAGAS report panel, NATIVE-REPORT-1.0 | Four named report rows: Faithfulness, Response Relevancy, Context Precision and Context Recall; preserve each native scale/variant/status | Rows are always present in the evaluation report, but scoring remains explicitly selected/configured offline work. Native requests can add judging/embedding work beyond the one custom-rubric bundle. ID-based precision/recall remain separately named optional diagnostics |

Do not rename custom scores as native RAGAS Faithfulness, convert0–1 into1–5, overwrite MET-16's existing human narrative rubric, or imply that risk recall equals evidence recall. RAG-R01–05 are five additional rubric dimensions; the23 existing MET definitions remain unchanged. Context relevance combines relevance, missing evidence and noise judgments and is not identical to native Context Precision.

RAGAS documents [user-defined rubric scoring](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/general_purpose/#rubrics-based-criteria-scoring), [native Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/), and [ID precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/#id-based-context-precision)/[ID recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/#id-basedcontext-recall). Built-in rubric scorers are not asserted to return the complete five-field bundle/examples or use one call. Implement the bundle and cached projections as a small custom adapter against the actually pinned RAGAS interfaces; verify score/detail propagation and outbound-call accounting before funded use. No exact unverified RAGAS API is prescribed here. A standalone prompt scored outside RAGAS is labeled MANUAL_OR_CUSTOM_BASELINE, not an executed RAGAS result.

## Standard native RAGAS report panel — NATIVE-REPORT-1.0

The user requested standard RAGAS scores in the report in addition to the five custom1–5 ratings. Add the following four common native metric families as a separate, always-visible panel in the OFFLINE EVALUATION REPORT. This is a reporting profile, not a claim that RAGAS defines one universal aggregate score. The custom rubric stays unchanged; a prompt-written score cannot populate a native row. Concrete layout: [evaluation report template](evaluation-report-template.md).

| Native report row / key | Native meaning and scale | Required input / applicability |
|---|---|---|
| Faithfulness / faithfulness | Response support against actual supplied context; native0–1, higher indicates more support | Actual response and frozen associated context. Missing context is INPUT_UNAVAILABLE, never a fabricated0 or1 |
| Response Relevancy (also called Answer Relevancy in some APIs) / response_relevancy | Alignment with the task/query; usually0–1. The documented cosine-based method can produce values in[-1,1]; preserve a legitimate negative raw value instead of clipping it | Actual task/query and response, verified evaluator model and embeddings configuration. Record the exact selected class/definition/version; a custom completeness/coherence score is not a substitute |
| Context Precision / context_precision | Native rank-aware usefulness of supplied passages;0–1 | Meaningful recorded retrieval order and the chosen variant's reference/evaluator inputs. The current unranked DIRECT package is NOT_APPLICABLE for this ranking score; never invent a ranking or substitute ID overlap under this label |
| Context Recall / context_recall | Required reference-supported information recovered in supplied context;0–1 | Actual context plus the reviewed evaluation reference required by the selected native variant. Can assess DIRECT evidence coverage where inputs fit; absent reference is INPUT_UNAVAILABLE. Keep reference separate from generation context |

Use native metric definitions from the actually pinned RAGAS version and record the implementation/variant. [Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/), [Response/Answer Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/), [Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) and [Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) are primary references. Response Relevancy's model-generated questions/embeddings can require extra work; neither its scale nor request count may be assumed from the1–5 rubric. Exact APIs/model support still require verification; no judge or embedding model is selected here.

Every row records metric_key/display_name, exact metric_identifier/variant, RAGAS package/configuration version, native scale, raw_score nullable, status SCORED/NOT_RUN/NOT_SELECTED/NOT_APPLICABLE/INPUT_UNAVAILABLE/FAILED/STOPPED, nonblank reason where not SCORED, evaluated sample/context/reference digests and relevant evaluator/embedding configuration. Validate finite raw values against the selected native definition: Faithfulness/Context Precision/Context Recall0..1; the documented relevance variant permits-1..1. Do not reject or clamp a valid negative relevance score merely to make every row0..1. Retain raw precision; a separately rounded display value does not overwrite it. No score is shown without actual package execution/validated metric output.

NOT_RUN means no execution, NOT_SELECTED means omitted by that explicit run manifest, NOT_APPLICABLE means the definition does not fit the recorded scope (for example ranked precision on DIRECT), and INPUT_UNAVAILABLE means a needed reference/configuration/actual-context input is missing. All use null raw_score and a readable explanation, not0/100%/Passed. A real measured0 remains SCORED and must be distinguishable from absence. Display per-metric scored/attempted/excluded/failed denominators when reporting a batch.

If IDBasedContextPrecision or IDBasedContextRecall are additionally selected, place them in a clearly labeled ID-based diagnostics block with their own native0–1 scores, scoped reference IDs and definitions. These useful no-LLM overlap diagnostics do not silently replace the four report families, rank-aware precision or reference-based recall. Likewise do not rename MET-23 precision@5 as a native RAGAS score unless that exact native implementation/definition executed.

Report order: execution/sample/context provenance; native four-row panel; custom five-score1–5 rubric with explanations/examples; optional ID diagnostics; independent critical checks/limitations; usage/cost and human adjudication. No blended custom/native mean, automatic universal RAGAS score or new release threshold. A native score never grants source currency/authority, factual support or credit permission. The credit memo remains the existing seven-section financial document; this evaluation report is its separate read-only quality artifact and must not score itself recursively or add an eighth credit-memo section.

Rows may be present before scoring while each clearly says Not run. Enabling report display does not enable calculation: native scoring still needs selected metrics, compatible evaluator/embeddings where required and a separately approved OFFLINE_EVALUATION allowance. The one-routine-request target applies only to the shared custom-rubric bundle; native Faithfulness/Relevancy/Precision/Recall may each dispatch additional requests. Explicit manifests must bound/count every judge and hosted embedding request (ADR-008), along with input/output, time and cost; unconfigured dependencies remain disabled. No model download, provider default, larger per-review allowance or paid call follows from this report addition.

## Frozen sample and grounding contract

RagEvaluationSample is a proposed internal application contract, not a third-party API. Required: evaluation_sample_id; case/split/variant and artifact scope; evaluated_subject SYNTHESIS_ORIGINAL/REVIEWED_WORKFLOW; original application mode FIXTURE/LIVE; original artifact/dependency digests; task/query and intended review outcome; exact response field-path/text projection; context_origin GENERATION_PACKET/RECORDED_WORKFLOW_INPUT/UNAVAILABLE; actual_generation_context nullable with exact context/scope/source dictionaries; validated financial/policy/risk results actually included there; ReviewSourceBasis/authority versions; evaluator_reference nullable; source-navigation/mechanical-check results; original cutoff and evaluator configuration/instruction versions. For SYNTHESIS_ORIGINAL, context must be its exact provider-visible ContextPacket. For REVIEWED_WORKFLOW, record the actual frozen renderer/workflow input snapshot with that distinct origin, never pretend it was a Synthesizer prompt. Absent context is explicit and yields affected NOT_EVALUABLE dimensions.

- Default subject is immutable original Synthesizer output before human rewriting under EVAL-CUTOFF-1.0. Observations, rationale, each condition and optional action reason retain NARRATIVE-CHECK-1.0 paths and references. A later corrected or human-edited workflow is a separately labeled sample, never a replacement for the original model result.
- The task is the actual deal-review objective, not an invented chat question. Completeness is judged against the supported scope and expected action, including a legitimate information pause. A financial decision is not required when evidence is missing. Failed/refused/unavailable outputs remain in attempted/failure counts; do not fabricate a response or successful score. A saved actual workflow pause may be evaluated as REVIEWED_WORKFLOW, never as generated Synthesizer output.
- Faithfulness uses ONLY the exact context associated with that subject/origin, including calculated/policy results actually supplied. For generated output this is the exact generation packet; for deterministic workflow output it is the separately labeled recorded input snapshot, not evidence of model quality. Evaluator-only references/expected points may inform completeness or diagnostic correctness, but must be kept separate. Never add a gold passage to the original context to make an unsupported answer appear faithful. No evaluator gold enters runtime prompts or grants support.
- Preserve complete scoped source/version/page/passage/calculation/policy/assessment handles and actual date/qualifier/authority checks. The evaluator may cite only supplied handles. It cannot browse, fetch more documents, change source precedence or decide applicability from memory. If essential evaluation inputs are unavailable, mark affected dimensions NOT_EVALUABLE rather than invent evidence.
- DIRECT contexts can be evaluated for support, relevance and completeness without a vector database. Native ranking-only retrieval metrics remain Not applicable for the unranked DIRECT baseline. Optional ID-based evidence comparisons and ranked-arm native diagnostics use RET-1.0/MET-23 frozen annotations and must not be presented as the same metric as precision@5 when definitions differ.
- Source existence and faithfulness do not prove currentness. An answer repeating an old calculator can be consistent with that context yet wrong for the selected date/tier/authority. Keep SOURCEFIT, citation resolution, financial correctness and permission checks as separate flags. A high rubric/native score cannot override a critical failure.

## User rubric, preserved as five distinct dimensions

| ID / dimension | What the evaluator must examine |
|---|---|
| RAG-R01 Faithfulness | How accurately the response reflects the supplied source context; hallucinations/incorrect statements; factual consistency. Check qualifiers, supported calculations and limitations without importing external knowledge |
| RAG-R02 Context Relevance | Whether selected passages are relevant to the task; important missing context; irrelevant information. Necessary full-extraction clauses, table context and conflict evidence are not noise merely because they are not quoted in the answer |
| RAG-R03 Answer Completeness | Whether the response addresses the task's key aspects with appropriate detail; identifies material issues and next action; correctly abstains or requests evidence when a final recommendation is unsupported |
| RAG-R04 Source Attribution | Whether material claims are cited, origins are distinguishable and references trace to exact supplied evidence. Separate source facts, calculations, policy results, authored assessments and reviewer corrections; no fabricated citations |
| RAG-R05 Response Coherence | Structure, logical consistency, flow and readability; a nontechnical reviewer can distinguish findings, uncertainties and next action. Clear writing cannot compensate for unsupported content |

Anchors below are versioned proposed implementation rubrics for the requested scoring scale; no score has been observed.

| Dimension | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| Faithfulness | Fabricated or contradicted central claims | Major unsupported claims materially change meaning | Mostly supported, with a substantive unsupported inference/qualification gap | Supported material assertions; minor wording imprecision | All assertions faithfully supported by actual context, with accurate qualifications/uncertainty |
| Context Relevance | Context does not address the task | Mostly irrelevant or essential evidence absent | Useful evidence mixed with substantial noise or an important gap | Relevant material present; minor unnecessary content | Relevant required evidence and qualifications/conflicts covered without distracting noise |
| Answer Completeness | Misses the task or invents completion | Major requested aspects/actions absent | Main task addressed with a substantive omission | Key aspects/actions covered; minor omission | All in-scope aspects covered at suitable detail, including correct abstention/limitations where required |
| Source Attribution | No usable traceability or fabricated citations | Most material claims untraceable/misattributed | Partial attribution with important gaps/unclear origins | Material claims traceable; minor locator/presentation weakness | Every material claim precisely traceable to its actual origin and supporting evidence |
| Response Coherence | Incoherent or internally contradictory | Difficult to follow with major structural problems | Understandable but repetitive, ambiguous or poorly organized | Clear and logically organized with minor readability issues | Concise, consistent and easy to follow, with clear findings/uncertainties/next steps |

Each score requires a concise explanation and at least one concrete example: quoted response field and evidence/context handle, or an explicitly identified missing required point/citation. Examples must be exact substrings or identified omissions; never fabricate a quote, page or missing passage. A5 still requires a positive supporting example. A single field containing several assertions must not receive full credit because only one clause is supported.

## Local output contract and results

RubricEvaluationResult contains evaluation_run_id/sample_id; protocol/rubric/RAGAS package/adapter/judge/prompt versions; original artifact identity/mode/subject/cutoff; result_origin MANUAL_BASELINE/CONTROLLED_ADAPTER/EXECUTED_RAGAS; execution_status NOT_RUN/COMPLETE/PARTIAL/FAILED/STOPPED; five named dimension objects; native_metric_results; independent critical_check_results; usage/cost/latency status and human_adjudication nullable. MANUAL_BASELINE is not package execution, and controlled adapters are not observed judge quality.

EvaluatorWire has exactly one root key dimensions, with exactly faithfulness, context_relevance, answer_completeness, source_attribution and response_coherence. Each dimension object has exactly status SCORED/NOT_EVALUABLE/NOT_RUN/FAILED; score strict integer1..5 only when SCORED, otherwise null; explanation nonblank for a score or unavailable/failure reason; examples list1..3 when SCORED and empty otherwise; evaluation_limitations list of strings. Every example has exactly kind SUPPORTED/UNSUPPORTED/OMISSION/ATTRIBUTION/COHERENCE, response_field_path nullable only for an omission, response_excerpt nullable for an omission, evidence_handles list, evidence_excerpt nullable and observation nonblank. Source/faithfulness examples require supporting or contradicting supplied handles; coherence may use response-only evidence, and an omission may identify an expected task point without inventing a source handle. Unknown fields, Boolean/string scores, score6 and fabricated quotes are rejected. Python validates schema/ranges, exact excerpt membership, scoped handles and flags, then hydrates RubricEvaluationResult metadata locally; the model does not return IDs/usage/model versions or grant support. Known absence is an omission, not a fabricated source handle. Unresolved mechanical failure cannot be rewritten by the judge.

Native results separately record metric name/definition/version/scale/raw score/status/input hashes; never infer them from custom scores. A custom-rubric run is COMPLETE only when all five dimensions are actually SCORED with valid explanations/examples and any additionally selected native results are available or explicitly justified Not applicable. A native-only run leaves all custom dimensions NOT_RUN and cannot claim that the five-score rubric passed. Otherwise record PARTIAL/FAILED/STOPPED as appropriate; no accepted result/empty sample population means no successful evaluation. COMPLETE describes evaluation execution, not a financial decision, quality pass or HHH certification. Persist exact original result and any separate human-adjudicated correction/disagreement with attribution. The local developer/instructor evaluation view in Activity shows five scores, explanations/examples, native diagnostics if measured, critical flags, provenance and costs. No sixth screen, ordinary risk dashboard metric or automatic per-deal judge execution.

Report per-dimension count/distribution/mean only across actually scored samples, with selected/attempted/scored/not-evaluable/failed counts, split and subject. No universal combined score or new RAGAS pass threshold is approved by this request; existing release gates remain. Do not average away a critical failure or treat missing results as0/1/5. Suggested thresholds require later calibration/approval; fixture scoring describes the fixture text, not live model quality. No HHH, regulatory or fairness certification follows from any score.
